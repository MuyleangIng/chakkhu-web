Why

Khmer is hard for a machine to read

Most OCR tools were built for English, where letters sit in one row, in the same order you type them. Khmer does not work that way.

Letters stack

In ស្ត្រី two letters sit under the first one. One "column" on the page can be three or four letters in the text.

Drawn order ≠ typed order

In កេ the vowel េ is drawn on the left but typed after ក. Reading strictly left to right gives the wrong text.

Khmer + English mixed

Chats, signs and menus mix both: តោះទៅ cafe ថ្ងៃនេះ. Today's free tools are weakest exactly here.

Architecture · the model

A small model built for Khmer

Big AI chat models that "see" pictures make 33–89% mistakes on Khmer. Small, specialised readers win, so Chakkhu is one: 18.6 million parameters (about 19 MB on a phone), trained from scratch, the same size class as the Akkhara keyboard model. Click a figure to zoom.

Why this design

  • Whole clusters, not letters. ស្ត្រី is one token (3,402 in total), so lines are 1.74× shorter and vowels drawn on the left need no reordering.
  • Knows Khmer before it reads. The decoder first learns from Khmer text alone, so blurry letters are guessed from the words around them.
  • Keeps the height. 64 px lines, 2 rows inside the model, so stacked letters above and below are not lost.
  • Never invents text. The CTC head counts the letters; if the decoder writes too much, its draft is used. Netra's run-aways were 17% of its errors.
  • Trained on the hard cases: short lines, English, night photos, Messenger images and chat screenshots.

Where Chakkhu wins

Documents: about half the mistakes of Netra on clean, Messenger, scanned and phone-scanned pages, and 2.6× fewer on short lines like signs and titles (8.7% vs 22.4%). On old 1990s–2000s government decrees: 2.1% errors. Still behind: street photos (6.4% vs 5.8%, night 11.2% vs 10.6%) and English-only lines.

We fixed the test first

In KHOB, the scanned and Messenger pages reuse the boxes of the clean PDF, so many boxes missed the text. We line up each scan with its clean page before cutting lines, and drop 2 pages whose pictures show a different letter.

How we score

CER = wrong, missing or extra characters ÷ characters in the right answer. Spaces and Khmer letter order are made consistent first (the same rules for every tool). Every labelled line is used (Netra's own 0.96% is on a 325-line selection). Same lines and rules for every tool; Chakkhu never trains on them.

Tools: Netra-OCR recognizer (19M, MIT) · Tesseract 5 with the best Khmer + English models, one-line mode. Benchmark: KHOB (MIT). Tested on 10 Nov 2026.

Use it

Read Khmer in your own code

Open model, Apache-2.0. Copy, paste, run. One picture = one text line; for whole pages use the API (it finds the lines for you).

Python (PyTorch)

Chakkhu-OCR-Khmer · best quality, CPU or GPU

# pip install torch pillow safetensors huggingface_hub rapidfuzz
import sys
from huggingface_hub import snapshot_download
folder = snapshot_download("muyleanging/Chakkhu-OCR-Khmer")
sys.path.insert(0, folder)
from chakkhu import load, read

model, tok = load(folder)
print(read(model, tok, ["line.png"], confidence=True))
# [("ព្រះរាជាណាចក្រកម្ពុជា", 0.99)]

ONNX (no PyTorch)

Chakkhu-OCR-Khmer-ONNX · int8, 39 MB, same accuracy (4.51%)

# pip install onnxruntime numpy pillow huggingface_hub
import sys
from huggingface_hub import snapshot_download
folder = snapshot_download("muyleanging/Chakkhu-OCR-Khmer-ONNX")
sys.path.insert(0, folder)
from chakkhu_onnx import Chakkhu

ocr = Chakkhu(folder)
print(ocr.read(["line.png"], confidence=True))
print(ocr.read(["line.png"], beam=0))   # fastest

Free API (whole pages)

Chakkhu-OCR-Demo · photo, scan or screenshot

# pip install gradio_client
from gradio_client import Client, handle_file

c = Client("muyleanging/Chakkhu-OCR-Demo")
r = c.predict(handle_file("page.jpg"), "page",
              api_name="/read")
print(r["text"])
for line in r["lines"]:   # text, confidence, box
    print(line["confidence"], line["text"])
